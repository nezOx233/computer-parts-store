# Ubiquitous Language — Computer Parts Store

**Практична робота №3.** Терміни, якими команда має користуватися однаково в документації, коді та обговореннях.

| Термін | Визначення | Контекст |
| --- | --- | --- |
| **Товар (Product)** | Опис комплектуючого, доступного для перегляду чи майбутнього продажу. | Catalog |
| **Каталог (Catalog)** | Набір відомостей про товари; не відповідає за фізичні залишки. | Catalog |
| **Залишок (On-hand stock)** | Кількість одиниць конкретного товару, фізично врахованих системою. | Inventory |
| **Резерв (Reservation)** | Кількість товару, тимчасово закріплена під майбутнє замовлення. | Inventory |
| **Доступна кількість (Available)** | `onHand - reserved`; не може бути від'ємною. | Inventory |
| **Покупець (Customer)** | Користувач, від імені якого може бути оформлено замовлення. | Users / Orders |
| **Позиція замовлення (OrderItem)** | Обраний товар, кількість і зафіксована ціна одиниці у копійках. | Orders |
| **Замовлення (Order)** | Сукупність позицій для одного покупця зі своїм життєвим циклом. | Orders |
| **Сума замовлення (Total)** | Сума `quantity × unitPriceKopecks` для всіх позицій; не дорівнює окремому платежу. | Orders |
| **Платіж (Payment)** | Відома системі спроба оплати конкретного замовлення зі статусом `pending`/`paid`/`failed`. | Payments |

## Неоднозначні терміни

- **`Item`:** у поточному коді та таблиці `items` — назва короткого запису каталогу (`id`, `name`). У доменній моделі така сутність називається **`Product`**, щоб відрізнити її від `OrderItem` — позиції конкретного замовлення.
- **`Status`:** не вживати без уточнення. **`Order.status`** описує життєвий цикл замовлення (`draft`, `placed`, `paid`, `cancelled`); **`Payment.status`** описує результат оплати (`pending`, `paid`, `failed`).
- **`Quantity`:** `OrderItem.quantity` — скільки хочуть придбати, а `StockItem.available` — скільки дозволено зарезервувати; це різні показники.
